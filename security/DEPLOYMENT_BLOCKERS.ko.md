# 인증 통합 후 운영 전환 조건 — 2026-11-16

운영 Firestore는 17:47 KST에 승인된 전체 거부 규칙으로 차단되었습니다. 공개 규칙 복원은 하지 않습니다. 이 브랜치의 후보 규칙은 미배포이며 기존 ERP의 서버 읽기·쓰기는 아직 복구되지 않았습니다.

## 이번 통합
- 기존 회사·직원·거래처 문서 ID를 유지하고 서버가 승인한 UID 소속만 사용합니다. 이메일 일치로 계정을 자동 연결하지 않습니다.
- tenantRead/tenantWrite callable 서버 경계로 회사·직원·거래처·번들·동기화 설정을 연결했습니다. 비밀번호·자격증명·기존 역할/권한 필드는 응답과 새 저장값에서 제거합니다. 운영 기존 데이터의 비밀번호 삭제는 실행하지 않았습니다.
- 직원 디렉터리는 업무에 필요한 필드만 반환하고 거래처 목록은 담당 직원 기준으로 제한합니다. 로그인/회사/권한 변경 시 이전 회사 캐시를 제거합니다.
- 후보 규칙은 승인·회사·기능 권한을 확인하고 알 수 없는 경로는 거부합니다. 인증만으로 전체 접근을 허용하지 않습니다.
- 기존 재고·상차·전표 계산 함수 100개 비교 결과 변경 없음. App 초기화/로그인, bundleSyncManager, firestoreSafety에는 인증 경계 연결 변경이 있습니다.

## 전환 전에 남은 조건
1. 현재 서버 구현은 Cloud Functions입니다. Spark에서 실제 배포하려면 Blaze 전환 결정이 필요합니다. 결제 설정은 변경하지 않았습니다.
2. 최초 플랫폼 관리자 UID와 기존 회사/직원 문서의 소유 관계를 명시적으로 확인해야 합니다. platformAccess/authz 생성과 운영 계정 연결은 별도 승인 대상입니다.
3. 거래처 partnerOrders 요청을 기존 수주/상차/전표로 전환하는 업무 연동은 미완료입니다. 요청 저장을 납품 완료로 표시하지 않습니다.
4. 실제 Google 팝업/리디렉션, 실제 인증 메일 수신, 브라우저 ERP 전체 화면/인쇄/오프라인 흐름은 미검증입니다. 로컬 Chromium 실행은 Unix 소켓 제한으로 실패했고 별도 클라우드 브라우저는 이 테스트 호스트에 연결되지 않았습니다. DOM 대체 검사도 로그인 후 진행에 실패하여 통과 근거로 사용하지 않습니다.
5. Functions Emulator worker도 Unix 소켓 제한이 있습니다. Auth/Firestore Emulator와 실제 onCall HTTP wrapper를 Express localhost에 올려 Firebase SDK httpsCallable로 호출하는 테스트를 실행합니다. 배포된 Functions의 CORS/App Check 검증을 대체하지 않습니다.
6. 기존 프로필 삭제와 관리자 권한 직접 편집은 제한됩니다. 승인 화면을 사용하고 전체 관리 화면 호환성은 추가 검증해야 합니다.
7. Antigravity 최신 브랜치와 최종 병합 후 승인 직원의 주문→상차→취소→재상차→납품→전표, 중복 제출, 재접속, 권한 회수 및 A/B회사 격리를 실제 브라우저로 다시 검증해야 합니다.
8. 운영 Rules/Functions/클라이언트 배포, main 병합, 계정 변경, 마이그레이션, 결제 전환은 별도 승인 후 실행합니다. feature/firebase-auth 자동 Vercel 배포는 비활성화 상태를 유지합니다.

## 재현
npm ci
npm --prefix functions ci
SKIP_BROWSER_FLOW=1 npm run test:auth
npm run build

테스트 프로젝트는 demo-linker-auth만 사용합니다. SKIP_BROWSER_FLOW는 브라우저 검사를 명시적으로 건너뛰며 통과를 뜻하지 않습니다. 모바일에는 해당 브라우저 테스트 파일이 없습니다.
